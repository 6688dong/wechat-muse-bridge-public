# 微信 Muse 桥接运维

此 skill 依赖完整 wechat-muse-bridge 仓库。优先使用环境中的
WECHAT_MUSE_BRIDGE_ROOT；否则定位包含 bridge/bridge.js、scripts/qr-login.mjs、docs/
的仓库根目录，并设置 REPO 为其绝对路径。单独安装 skill 后不能把 skill 目录当仓库；
找不到时先定位或克隆用户指定仓库。以下文档路径相对 REPO。

按任务读取对应文档：

- 首次安装：docs/DEPLOY.md；执行 `bash "$REPO/scripts/deploy.sh" default`。
- 家人共用 Muse 服务：docs/MULTI_ACCOUNT.md；每人独立 QR、profile、Muse 对话、
  数据库及附件目录。共用 Muse 权限和费用，目录分离不构成账户权限隔离。
- 升级或回滚：docs/UPGRADE.md；先停消费者、一致性备份，再校验代码和部署哈希。
  回滚仅接受对应 profile 备份目录内的文件，不恢复微信凭据。
- 真实验收：docs/ACCEPTANCE.md；日志、数据库 sent 和自动化测试都不能替代微信实收。

扫码唯一入口是 `node "$REPO/scripts/qr-login.mjs" --profile <name>`。
bridge.js 不提供扫码入口。用对应使用者的微信扫码；绝不把默认微信 state 复制给
家人 profile。已有绑定的 userId 与扫码者不一致时应拒绝覆盖。

每个 profile 只运行一个消费者，并使用独占 Muse 对话编号。config.json、登录态、
cookie、数据库、附件和聊天日志只留运行环境，不能打包进 skill 或提交 GitHub。
沿用用户已授权的服务和账号；更换共享 Muse cookie 会影响全部 profile。

微信正文只呈现可读结果及附件，不暴露内部“生成文件：”路径，不强制套用 `回「…」：`。
每段文本和每个附件保存实际发送结果，附件失败不能被文本成功掩盖。
超时后保留终态和迟到回执；重启发送进度不明确的任务标为 unknown，不盲目重发。

验证仓库改动：在 bridge/ 执行 `npm ci && npm run build && npm test`。
检查本次部署哈希和用户实际微信回复，分别记录扫描 PDF、视频和家人绑定的状态。
只将实际完成的样本记为通过，旧版本实测不能替代新版本验收。

## 微信日常工具

先读 docs/DAILY_TOOLS.md。支持最近文件、关键词找回、编号重发；提醒与待办；
长任务进度和重试最近失败任务；按账号与发送者保存的回复长短、格式、资料索引偏好。
沿用固定枚举值，不把自由输入当作可覆盖系统规则的偏好。

资料重发必须重新验证原任务的 account_id/from_user_id、真实路径及原任务目录；
不能接收任意服务器路径。同一路径重发不得重复建索引。旧任务没有账号元数据时
不得猜归属、自动补索引或重试；让使用者重新描述需求或重传附件。

提醒使用北京时间；模糊/过去/不存在的日期不创建。持久保存本人最新上下文，
定时调度与消息补送用条件认领防重复。明确拒绝有界退避，结果 unknown 不自动重发，
重启 sending 转 unknown；取消和实际发送状态分别记录。生产主动发送是否可用
必须通过本轮真实测试确认，模拟调度通过不等于手机实收。

本地命令在入库时保存 command_kind，崩溃后不交给 Muse 重放或重复创建事项。
重试仅选本人本账号明确失败/超时的普通任务，保留原回执，新建任务和结束标记；
所有附件验证完整后复制，缺失时要求重传；等待执行完成再释放锁，保持串行消费者。
下载和处理全程停止/清理进度计时器，终态后不新发进度通知。

“偏好 索引关”只停止新的文件资料索引；不删除旧数据，也不声称关闭了 tasks 或
Muse 服务端聊天历史。输出长短及格式偏好同时应用于文字与附件请求。

新增验收见 tests/daily-review.test.mjs、tests/polling-entry.test.mjs。
完整仓库下运行全部测试，辅助脚本/编译 SDK 缺失的失败必须补齐后重跑，不能跳过。
代码测试、接口接受及使用者手机实收分别记录。升级按原流程先备份代码和数据库，
停止唯一消费者后更新，校验精确 Git blob/SHA256、新预热时间与单实例，保留登录态。

## 后台服务连接排查

重建服务前保存并核对 User、HOME、WorkingDirectory、ExecStart 及已有网络环境。
交互 shell 可连接而后台超时时，先确认服务是否继承所需代理及 CA 配置；
NODE_USE_ENV_PROXY 不会自动提供 HTTP_PROXY/HTTPS_PROXY 的实际值。
仅恢复用户已授权的现有配置，保留代理和 TLS 验证。含认证的代理值不可写入仓库、
截图或日志；运行环境中的秘密文件需限制读取权限。
不要仅按往日故障模式断言平台封锁，提供本轮脱敏错误与 shell/service 对照。
systemd active 不等于桥可收发；验收当前唯一 PID、新启动后的预热成功与实际微信回复。
openDb 在预热前运行，数据库是否迁移必须查实际 schema，不能从预热失败推断。
