# 微信桥日常工具

## 资料找回

微信发送：
- `最近文件`：最多十项，显示名称、日期、大小与编号。
- `找文件 报告`：按文件名搜索。
- `再发文件 1`：重新发送编号对应的实际附件。
- `把昨天那份表格再发我`：按北京时间日期和文件类型查找，多个匹配会先列候选。

收发文件索引按账号、发送者隔离。索引和重发均检查原任务账号、发送者、文件存在
及 realpath 在原任务目录内；拒绝跨任务符号链接和任意路径。重复重发不会增加索引。
旧任务没有账号元数据时不猜归属，不自动纳入索引或重试；需要重传附件。

## 提醒与待办

微信发送：
- `提醒我 10分钟后 开会`（也支持 `提醒我10分钟后开会`）
- `提醒我 明天上午9点 交报告`
- `提醒我 2027-01-01 09:00 新年计划`
- `提醒列表`、`取消提醒 1`
- `待办 买牛奶`、`待办列表`、`完成 1`、`取消待办 1`

时间按北京时间解释，相对时间从当前时刻计算。模糊时间先询问，不创建提醒；
过去时间、负数/小数相对时间、不存在的日期会拒绝或要求换一种明确说法。
提醒和待办持久保存在本 profile 数据库；事项归属限定账号及发送者。

后台每三十秒检查提醒，使用本人的最近会话上下文，条件认领防止与补送重复。
明确拒绝最多三次发送尝试，失败后按一分钟、五分钟退避；耗尽后等待本人新消息。
没有有效上下文时也等待新消息。新消息更新上下文并补送已到期事项，尊重退避；
取消命令先处理。网络结果不明记 unknown，不盲目重发，下次只告知一次可能已发送。
重启时 sending 转 unknown，保留记录。平台可能拒绝主动发送，必须以本轮接口
接受及手机实收确认可用性；自动化测试不能代替真实微信验收。

## 长任务进度与重试

普通任务超过约十秒会发处理中通知，后续在约九十秒、二百四十秒通知并节流；
覆盖下载阶段。短任务结束会清理计时器，终态后不新发进度，不猜完成时间。
通知各自使用独立发送编号，微信正文不会显示内部路径、任务编号或堆栈。

`重试最近失败任务`（或 `重试`）创建一个新任务，保留原任务和回执。
只选择本人本账号明确失败或超时的普通任务，不重放本地命令和 unknown 任务。
附件必须全部可验证、已下载完整，复制到新任务目录后处理；无法验证时要求重传。
等待执行结束后释放原任务的重试锁，保持同一消费者串行处理。

## 个人偏好

- `偏好查看`
- `偏好 简短`、`偏好 详细`、`偏好 标准`
- `偏好 纯文本`、`偏好 Markdown`、`偏好 列表`
- `偏好 索引关`、`偏好 索引开`

每个账号和发送者独立保存。回复长短与格式通过固定字段作用于文字和附件请求；
不允许自由输入覆盖桥接规则。`索引关`停止新文件索引，已有索引和附件仍保留；
tasks 仍保存运行所需正文与记录，也不会关闭 Muse 服务端聊天历史。

## 维护与验证

沿用 docs/UPGRADE.md 的备份、停止消费者、升级及回滚流程，保留登录态。
部署前完整运行仓库检查；目前共六十项用例，包含原有三十二项、二十项日常工具、
一项真实轮询入口、四项附件重试及三项任务目录校验。新功能用例读取实际 bridge.js，覆盖隔离、失败、重启、
回执、退避、进度和串行重试。缺少辅助文件时先补齐，不能将失败当作通过。
代码检查、接口接受及手机实收分别记录，视频人声等未完成的真实验收仍保留待办。

重建后台服务时核对原运行用户、HOME、工作目录、启动命令和网络环境。
交互 shell 正常、后台连接超时时，先检查实际代理和 CA 是否继承；仅设置
NODE_USE_ENV_PROXY 不会补齐 HTTP_PROXY/HTTPS_PROXY。代理认证值只留受限运行环境。
依据本轮脱敏错误定位原因，不按旧故障猜测平台限制。检查当前唯一进程与新预热记录；
服务 active 不能代替微信收发验收。数据库迁移须查实际 schema，因其可能早于预热执行。
