# 微信真实验收

自动化检查和日志用于定位问题；实际微信收到正确内容才能算完成。旧版本成功不能
替代新候选的微信实测。每次记录部署哈希、profile、任务编号和唯一测试标记。

## 文本和附件回复

1. 在绑定微信的 ClawBot 对话发送新的唯一标记，要求原样回复。
2. 确认实际收到回复，没有机械的 `回「…」：` 前缀。
3. 请求两个文件，确认微信收到能打开的附件，正文不显示内部目录或“生成文件：”指令。
4. 执行 `bash "$REPO/scripts/verify.sh" default "唯一标记"`，核对部署哈希、单消费者，
   status/send_receipt 及每段文本、每个附件的实际回执。

附件发送失败时不能仅因文本发出就标为 sent。空回复且无附件不算成功。
`send_attempts` 是历史重试计数，不是已发送分段数；以逐段/逐文件回执和微信实收为准。
unknown/pending 不得盲目重发。

## 扫描 PDF

准备无文本层的扫描 PDF，中文字体可辨认，包含预先记录的姓名、日期、电话号码、
金额及至少一张表格。先人工检查每页图像，再由用户从微信发入。
比对 OCR 返回的关键值、表格行列及遗漏；记录任务和实际回复。
先前字体不可读的扫描样本不合格，新样本生成或发送也不等于 OCR 已通过。

## 视频

准备一段有可辨文字、动作和语音的短视频，预先记录答案。由用户从微信发入，确认
时长、抽帧内容和语音结果正确；若缺少语音工具，应如实记录未覆盖语音。
只生成视频或调用 ffmpeg 成功不足以证明微信端到端成功。

## 家人连接

默认微信和家人微信分别发送不同的标记和附件。核对 Muse 对话编号、数据库、附件
目录均不同，回复只回各自微信；家人账号不能读取或迁移默认账号的登录 state。
共享 Muse 权限的限制见 [MULTI_ACCOUNT.md](MULTI_ACCOUNT.md)。

## 当前证据范围

旧版本文本实收已有用户确认；Excel、Word、文本 PDF、PPTX 只覆盖已有样本。
脱敏后的范围见 [公开验收摘要](../FINAL-REPORT.md)：扫描 PDF 中文关键字段及表格、
视频画面已有样本验证；两套独立部署已确认微信文件实收，其中一套完成提醒实收。
清晰人声样本已做本地转写检查，但视频声音的微信端到端验收仍待完成。
须用有已知清晰人声的新样本核对转写及微信实收；家人或另一 Muse 环境独立记录。
安装检查、退出码 0、数据库 sent 均不能替代有效内容和用户实收。

## 超时与故障回归

检查 CLI/history 挂起、缺少任务结束标记、迟到回复、媒体进程挂起、多附件途中超时、
超时后返回发送回执和重启中间任务。确认终态不被迟到结果改写、无取消后的新发送、
无重复发送、无孤儿媒体进程。故障后观察至少 30 秒，并保留逐段/逐附件回执。
